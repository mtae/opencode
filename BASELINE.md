# Baseline: per-step session-history reload (Phase 1)

Branch: `session-history-cache` (based on `origin/dev` @ 8c173a8f). Measured 2026-10-17 on Windows 11, Bun 1.4.3,
in-memory SQLite (`:memory:` via test preload pattern). Synthetic sessions generated by
`packages/core/script/benchmark-session-history.ts` (user messages with 256-char text unless noted; one instruction
state prepared; `boundary=local`). Protocol: 3 warmup + 15 measured runs per point, median + MAD reported.

Instrumentation: `OPENCODE_SESSION_HISTORY_TIMING=1` (added in this branch, removable) emits per-phase ms to stderr.
The benchmark script also times `entriesForRunner` and `toLLMMessages` wall-clock per run.

## Assumption verdicts

- **A1 (per-step full reload is dominant per-step CPU cost):** Not yet confirmable for real end-to-end steps.
  Synthetic reload is ~60 ms at 5k messages and ~167 ms at 20k; `toLLMMessages` adds ~32/94 ms.
  Whether this dominates a real `runStep` depends on model latency and tool execution, which this benchmark
  does not include (no network). Baseline establishes the cost of the reload itself; A1 needs a real-step
  profile. Provisional: reload is a measurable, growing cost (O(n) in messages) but not obviously dominant
  vs. model calls.
- **A2 (SQLite read cheap, decode is the cost):** Partially confirmed. At 20k messages, SQL read 65 ms vs
  decode 97 ms; decode is ~1.5x SQL. Both grow linearly; decode is the larger component but SQL is not
  "cheap" (it is ~40% of the phase). Neither is negligible.
- **A6 (store.context / settleStaleToolCalls matter):** Not dominant. `store.context` is the same
  `SessionHistory.load(..., "latest")` and is called once per drain (`llm.ts:72`) plus read-tool discovery
  paths. Per the audit (`SESSION-PERF...` companion), it is not on the steady-state per-step hot path;
  include it in any cache scope but do not optimize it standalone.

## Caveats

- In-memory DB; no OS page-cache/SQLite file effects. Real DB at
  `C:\Users\aahlad\.local\share\opencode\opencode.db` may differ (measure separately on a copy).
- Synthetic messages are all `user` type with repeated text; real sessions mix assistant/tool/reasoning and
  compaction checkpoints. Decode cost scales with JSON size and shape.
- N=15 runs but not interleaved across scales in this pass; A7 recommends interleaving to decorrelate drift.
- No end-to-end `opencode run` measurement here; model latency dominates that path (~900 ms per handoff §2).

## Reproduce

```
cd packages/core
OPENCODE_SESSION_HISTORY_TIMING=1 bun run script/benchmark-session-history.ts --messages 5000 --runs 15 --warmup 3
```
Add `--compaction 1` for checkpoint variant, `--text-size 1024` for larger outputs, `--boundary latest`.
